## 2. The change (v1) in the mob-defaults repository

1. `safety_policy.py` (new, the single source of truth) with: `DENY_PATTERNS` (the five of the owner: `rm -rf`, `rm -r`, `Remove-Item -Recurse`, `rmdir /s`, `del /s`, plus `rm -fr`, `rm -R`, `rm --recursive`, `rd /s`, `rmtree`, `git clean -f`, `find ... -delete`); `refuses(command) -> str | None` (the pattern name that makes the command a recursive delete, or None; `rm file`, `Remove-Item file`, `git worktree remove P`, `git clean -n`, `echo rm -rf x` are NOT refused; `cmd /c rd /s /q x`, `bash -c 'rm -rf x'`, `python -c "shutil.rmtree(x)"`, `Get-ChildItem | Remove-Item -Recurse`, `find . -name x -delete`, `git clean -fdx` ARE); renderers `claude_settings() -> dict`, `grok_deny_args() -> list[str]`, `cursor_deny() -> list[str]`, `copilot_deny_args() -> list[str]`, `codex_rules() -> str`, `aider_args() -> list[str]`; `hook_decision(payload: dict) -> tuple[int, str]` (exit 2 and a reason for a payload whose command is refused, exit 0 otherwise; payload shapes: Claude `{"tool_name","tool_input":{"command"}}`, Cursor `{"command"}`, agy `{"toolCall":{"args":{"CommandLine"}}}`); `log_refusal(path, driver, command)` appending one JSON line; `launcher_problems(backends: dict) -> list[str]` (empty when every enabled backend that can run shell commands carries its deny wiring: claude invocation has `--settings`, copilot invocations have `--deny-tool`, grok invocations have `--deny`, and the committed deny files exist and equal the rendered text).
2. Committed deny files rendered from the policy, in this repository and in the avowry repository (both, so every clone and worktree carries them): `.claude/settings.json` and `.cursor/cli.json`.
3. Launcher wiring: `core/backends.json` (claude `--settings .claude/settings.json` relative to the seat's cwd, copilot `--deny-tool`, grok `--deny`), `grok_write.grok_command`, `cursor_write.agent_command` / `cursor_reply` (read the committed `.cursor/cli.json` from the worktree), `local_driver.aider_command` (`--no-suggest-shell-commands`), and a shared pre-launch check (`launcher_problems`) that makes `cursor_write`, `muse_write`, `grok_write` and `local_driver` refuse to start (setup error 2) when the committed deny files are missing or differ.
4. `hooks/delete_guard_hook.py` strict mode `--deny-all` using `safety_policy.hook_decision` and logging each refusal to `.mob/safety/refusals.jsonl`.
5. `remove_throwaway.py` (new, the ONE reviewed cleanup helper; run by the facilitator only, never by a seat): one literal absolute path argument; refuses unless the real path (no symlink or junction) is a strict child of an allow-listed parent with a leaf matching `gate*-clone`, `signoff*-clone`, `gate*-review-*`, `wt-*`, is a git work tree, is not a main checkout (the first entry of `git worktree list`), not the current directory or a parent of it, not a drive root or the home directory, and clean (`git status --porcelain` empty) unless `--force-clean`; a linked worktree goes through `git worktree remove`; a plain clone is removed by the helper itself (the one reviewed place a tree removal exists; state this plainly in its docstring); every attempt (removed or refused, with the reason) appends one JSON line to `.mob/safety/removals.jsonl`. Seats only REPORT the path of a throwaway; the brief templates say so.
6. Not in v1: live quota-spending tests for every driver; the Muse and agy hook spikes beyond config text (filed as a follow-up if unverifiable); the Codex rules effectiveness under `powershell -Command` (the strict hook is its backstop).

## 5. Risks

Over-blocking (`Bash(*rm -r *)` also blocks `git rm -r`; Copilot's `shell(rm)` blocks single-file `rm`: accepted for seats, the strict hook does the real parse); Windows aliases defeat PATH shims (rm, ri, del, rd, rmdir are aliases of `Remove-Item`; so no shim approach); `--bare` skips Claude hooks (the deny settings are the robust layer); unverified items stay config-text tests (Grok, Cursor, Copilot, Muse, agy; Codex under `powershell -Command`); the helper itself performs a tree removal for plain clones, so the hook must exempt exactly the helper by a pinned sha256, and only the facilitator runs it.
