## 5. Risks

Over-blocking (`Bash(*rm -r *)` also blocks `git rm -r`; Copilot's `shell(rm)` blocks single-file `rm`: accepted for seats, the strict hook does the real parse); Windows aliases defeat PATH shims (rm, ri, del, rd, rmdir are aliases of `Remove-Item`; so no shim approach); `--bare` skips Claude hooks (the deny settings are the robust layer); unverified items stay config-text tests (Grok, Cursor, Copilot, Muse, agy; Codex under `powershell -Command`); the helper itself performs a tree removal for plain clones, so the hook must exempt exactly the helper by a pinned sha256, and only the facilitator runs it.

## 6. Cycle 2 (hardening after the second review; same card, before the gate review and the sign-off)

The second read-only review (second-review.md, ACCEPT WITH NOTES) found, with the failing inputs: (1) the committed Claude and Cursor deny globs miss ordinary recursive deletes (`del /f /s /q x`, `rm -Rf x`, `rm -rv x`, `rm x -rf`, `ri -r x`, `Remove-Item -Path x -r`, mixed-case `-recurse`, `rd/s/q x`, `rmdir x /s`, `git clean --force`, `git -c k=v clean -fd`); the broad judge `refuses()` runs only in the strict hook, which is installed nowhere; (2) `refuses()` misses shell keywords (`for ...; do rm -rf $d; done`, `if ...; then rm -rf x; fi`, `! rm -rf x`), wrappers (`timeout 5 rm -rf x`, `nice -n 5 rm -rf x`, `eval 'rm -rf x'`, `%ComSpec% /c rd /s /q x`), quoting (`"rm" -rf x`, `r''m -rf x`), a flag cluster (`rm -rfdvi x`), `from shutil import rmtree as r`, and `Get-ChildItem x -Recurse | Remove-Item`; (3) false positives: `echo 'shutil.rmtree is banned'`, `git commit -m "x; rm -rf y"`, `grep -n rmtree remove_throwaway.py` (the `Bash(*rmtree*)` glob); (4) the cleanup helper removed a plain clone with a matching leaf (by design: a throwaway), but also silently deleted a clone holding a NESTED git repository; (5) `cursor_reply.py` without `--worktree` starts with no deny-file check; (6) Muse, agy and Codex have no enforcement while the headline says "every seat launcher".

Cycle 2 scope (tests first, then the green; red and green on different seats):
- R2-1 `refuses()` is a shell-aware judge: it splits a command into segments (`;`, `&&`, `||`, `|`, newlines, `$(...)` and backticks), strips wrappers (`env`, `sudo`, `command`, `\`, an absolute path to the verb, `timeout N`, `nice -n N`, `xargs`, `eval`, `bash -c` / `sh -c` / `cmd /c` / `powershell -Command` bodies, `%ComSpec%`), joins quote-split words (`"rm"`, `r''m`), and decides on the VERB and its flags: `rm` or `ri`/`erase`/`Remove-Item` with any recursive flag in any position or cluster (`-r -R -rf -fr -Rf -rv -rfdvi --recursive`, `-Recurse` and `-recurse`, case-insensitive, also `-r` after the path), `rmdir`/`rd` with `/s` or `/S` in any position (also `rd/s/q`), `del`/`erase` with `/s`, `git clean` with `-f` or `--force` (any `-c k=v` before it; `-n` alone is allowed), `find ... -delete`, `robocopy ... /mir` or `/purge`, and `python`/`py` code naming `rmtree` (including `from shutil import rmtree as r`), `Get-ChildItem ... -Recurse | Remove-Item`. A segment whose verb is `echo`, `printf`, `grep`, `rg`, `git commit`, `git tag`, `gh ... --body` or similar only carries text: its arguments are NOT judged. `rm file`, `Remove-Item file`, `git worktree remove P`, `git rm --cached f`, `git clean -n` stay allowed (`git rm -r` is refused: documented false positive).
- R2-2 The rendered Claude settings gain `hooks.PreToolUse` (matcher `Bash|PowerShell`, command `python <absolute path of hooks/delete_guard_hook.py> --deny-all`) so every Claude seat and session runs the broad judge, and the `permissions.deny` globs gain the missed forms (`del /f /s`, `del /f/s`, `rd/s`, `rmdir * /s`, `git clean --force`, case variants of Remove-Item and -Recurse, `ri -r`), and lose `Bash(*rmtree*)` (the hook judges it instead). The committed `.claude/settings.json` in both repositories equals the render.
- R2-3 New rendered, committed hook files: `.cursor/hooks.json` (a `beforeShellExecution` hook running the same command; exit 2 blocks) and `.agents/hooks.json` (a `PreToolUse` handler on `run_command`, payload `toolCall.args.CommandLine`); config-text tests only (the behaviour is unverified for agy under `--dangerously-skip-permissions` and for Cursor's hook schema: say so in the file's neighbour note and in the retro).
- R2-4 `remove_throwaway.py` refuses (exit 1, reason named) a clone that contains a nested git repository (a `.git` directory or file below the root, other than the root's own); every earlier behaviour is kept.
- R2-5 `cursor_reply.py` without `--worktree` checks the committed deny files of its own repository (exit 2 when missing).
- R2-6 Honest documentation: `safety_policy.py`'s docstring, `core/backends.json`'s comment and the brief template line say that Claude, Grok, Cursor (write) and Copilot are enforced, aider needs no deny, and Muse, agy and Codex are NOT enforced yet (follow-up spikes filed as a bug); seats REPORT the path of a throwaway and never delete it.
