# D284 proposal: card 165 and the Slice 142 explicit `uses web` byte check

Card 165 (failure observer, D283) puts each failure's step id into the generated C# as a constant, so a production log line can be traced offline. Step ids are card 161's scheme: sha256 of kind, source line, name and (for failures) endpoint. The map bytes must not change (MapCultureInvariance and the map tests), so the scheme stays.

The second green proof (full Status!=Pending suite under Avowry's heavy lock, 07:15 to 07:30Z): compiler 344 of 344, acceptance 1576 of 1578. One remaining failure is a conflict, not a bug: `WebExtensionBoundary.Orders_phrase_loads_web_and_keeps_the_output_recorded_before_the_slice` (Slice 142) compiles orders.avowry twice, once as is and once with an inserted `uses web` line, and asserts identical generated bytes (line 42). The inserted line moves every declaration down one line, so every failure step id changes, so the generated bytes differ. Before card 165 the generated C# held no line-derived data, so the check held. (The other failure is the demo golden, which the facilitator re-records; not part of this vote.)

Card 142's acceptance criterion 1 asks that an explicit `uses web` "loads the same set"; whole-output byte equality under a shifted source is the test's own stricter check. The re-recorded orders hash itself (the as-is compile) passes.

## Options
A (recommended). Amend the Slice 142 test's explicit-file check, test-only, by the red seat: compare the two outputs byte for byte after replacing each 12-hex value on the generated `FailureStepIds` constant lines with a fixed placeholder, and additionally assert that each explicit-file step id equals `SourceMapIds.StepId("failure", line, code, endpoint)` for its shifted declaration line. A `//` comment names card 165 and this decision. The as-is hash pin stays exact. No product change; card 161's scheme and the map stay byte-identical.
B. Drop the source line from the step id. Changes card 161's scheme and every map's bytes; breaks MapCultureInvariance and the map pins; out of card 165's scope.
C. Keep step ids out of the generated C# and look them up at run time from the map. The map is never deployed (SourceMapDeployment), so production lines could not carry a step id; defeats card 165-2.

Vote Yes to adopt A, or No with the option you prefer and why.
