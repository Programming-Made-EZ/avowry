## 2. Guard design (carries over to the revised card with the new definition)

- Definition for the revised card: a class asserts a wall-clock limit (see ready-body.md). Unit of decision: each top-level class on its own text span, nested types included in their parent; a test class is one that directly holds a [Fact] or [Theory]; a partial class is merged by class name across files (passes if any part carries the attribute; reported once at the first part in ordinal path order); several classes in one file are judged separately.
- Blanker (one single pass in the guard file, returning a Code variant with comments, string contents and char contents blanked and a Text variant with comments blanked only; newlines kept; CRLF normalised to LF first: four files are CRLF: GeneratedApiBoundAddress.cs, GeneratedApiBoundAddressEdges.cs, GeneratedApiHazards.cs, HoldoutTaskConversion.cs): handle `//` and `/* */`, regular strings with `\"`, verbatim `@".."` with doubled quotes (multi-line), interpolated `$".."`, `$@`, `@$` (holes skipped with nested strings and comments, recursively), raw `"""` strings of any run length, interpolated raw `$$"""` (hole braces counted by the number of `$`), char literals (`'"'`, `'\''`, `'\\'`, `'{'`). Support/CSharpLiteralScanner.cs (lines 110-240) shows how holes and raw strings are read but returns literal bodies and cannot be reused; NoBlockingProcessWaits.Blank (lines 177 to 242) is not hole-aware (its header says so, line 11). CSharpBaselineAcceptance.cs contains many `class` declarations inside raw string literals: a scanner that does not blank strings first invents phantom classes. Class declarations: `(?<![:,]\s)\bclass\s+(\w+)` on the Code variant (avoid `where T : class`), span by brace matching on Code.
- Attributes: walk backwards from the `class` keyword over whitespace and modifiers (public, sealed, static, abstract, partial, internal, file), collect each `[...]` group by bracket matching, read each group's text from the Text variant; accept only `Collection("<exact name>")` or `Xunit.Collection("<exact name>")` with one literal string; reject other spellings (different case, a trailing space, CollectionAttribute(...), a constant, name: forms, a commented-out attribute).
- Reporting: an xunit test; `Assert.True(cond, message)`; a header line without class names, then one line per offender sorted ordinally by file then class: `  tests/Avowry.Acceptance.Tests/<File>.cs: <Class> ...`; never echo source lines; fixtures call a private `Find(IEnumerable<Source>)`.
- Root and skips: `RepoPaths.Find("tests", "Avowry.Acceptance.Tests")`; stack walk skipping bin, obj, .git, node_modules, TestResults as NoBlockingProcessWaits.ReadAcceptanceSources does (162-174); relative path with `/`.
- 2.6 TRAPS for the guard file: GeneratedApiSourceScan.Guard_checked_set_of_process_start_callers (lines 81-90) reads the raw text of every .cs and requires an exact allow-list of 23 callers: the guard file must not contain the process-start literal anywhere, even in comments (build it by concatenation `"Process" + ".Start("`, fixtures too); avoid the literals `FreeLoopback` + `Port` and `new Tcp` + `Listener(`, a `static int` helper whose name contains Port, Free, Unused or Available (line 74's regex), the URLs environment variable literal; NoBlockingProcessWaits (lines 17-25) forbids `.Result`, `.Wait(`, `.ReadToEnd(` (even for a StringReader), `.WaitForExit(`, `GetAwaiter().GetResult(` in code and a member named Result (use Verdict); in fixture strings use plain or `@""` strings on concatenated lines, avoid raw `"""` literals and nested-quote interpolation; tests/test_bench_launcher_scan_264.py flags any line containing the quoted literal `"--project"` in a .cs that matches `Avowry\.Bench\.csproj`, `RunArm("Avowry.Bench"` or `Project: "Avowry.Bench"`: do not write those patterns or the quoted `"--project"`; no drive-letter-plus-Users path, no /home/, no personal name (home-path and account-name guards); no PH-code; no delete calls; the revised guard's definition mentions `Elapsed` and `CancellationTokenSource`: the fixtures build those words by concatenation or inside strings, which are blanked.
- NOTE (revised card): the revised guard's fixture rows are Z1, O1 (an `Elapsed <` comparison), O2 (a CancellationTokenSource with TimeSpan.FromSeconds), O3 (attribute spellings and placements), B (comment, string, a process-timeout argument that is not a wall-clock assertion, wrong collection names), I (string literal forms, several classes in one file, a partial class, bin and obj copies, the guard's own file), L1 (live tree, Pending: fails naming BenchmarkHarnessAcceptance), L2 (born green: the detected set contains BenchmarkHarnessAcceptance, so a blind blanker cannot pass L1 forever).
