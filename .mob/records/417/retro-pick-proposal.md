THE PROPOSED ENTRY (it REPLACES the D247 entry; verbatim from the patch):

- **A test that asserts a wall-clock limit runs alone in an isolated collection (experiment; card 368 retro, Decider D247; rewritten by the card 417 retro, Decider D254).** While this entry is on trial: an acceptance test class that asserts a wall-clock limit (a stopwatch's `Elapsed`, total seconds or total milliseconds compared with a limit, or a cancellation token created with a time limit and used to fail a test) carries `[Collection("Isolated timing")]`; one `[CollectionDefinition("Isolated timing", DisableParallelization = true)]` exists in the test project, so xunit runs that collection after every parallel collection has finished, with nothing else running; the guard test `WallClockTestsRunIsolated` (card 417) fails the build when a class that asserts a wall-clock limit does not carry the collection, and its test of the definition fails when the definition is missing or weakened, so the independent gate reviewer no longer checks this by hand; the earlier remedy of D247 (the shared `[Collection("Bench processes")]` for classes that start the bench tools) is dropped as a remedy for a time limit: it did not stop the timing test failing under load (card 418: twice), because the load came from other parallel classes; the classes that already carry it may keep it as a harmless grouping. The DETECTION rule is written down and enforced by committed regular expressions, not by a reviewer's judgment: the guard (the file `tests/Avowry.Acceptance.Tests/WallClockTestsRunIsolated.cs`, whose header and two constants hold the exact patterns) blanks comments, string contents and char literals first, then names a class when its code compares `Elapsed`, `TotalSeconds` or `TotalMilliseconds` with a limit using less-than or less-than-or-equal, or creates a cancellation token source with a `TimeSpan.FromSeconds(` or `TimeSpan.FromMilliseconds(` argument and fails a test with the words "did not finish within"; the known spellings it misses (the spelling gaps of bug 430: `ElapsedMilliseconds`, a variable limit, `Assert.InRange`, a reversed comparison, `FromMinutes`, `WaitAsync` and the like) are a defect, not a loophole: a missed spelling is filed as a bug and fixed by widening the patterns with a failing fixture test first, and a reviewer who sees a wall-clock assertion the guard does not name raises it at once.
