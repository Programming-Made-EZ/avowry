## Criteria (D157: one red-green cycle each; each red commit body says "Criterion: n"; green n before red n+1)

Allow-list (D169, decided here): the scan's allow-list is UNCHANGED, a literal strict child of `scratch`; the card says so as an invariant, and "inside the working tree" is too wide for a detector (a repository's own `src` would pass). The tree rule belongs to the hook: it refuses every recursive delete whose targets are not all literal paths inside the working tree; inside the tree but outside scratch the scan reports and the hook allows.

Acceptance (outside-in), fixture transcript with one tool call per form: `python delete_guard.py scan-transcript <fixture> --seat "red ctx-3"` exits 1 and prints one line per form `seat: kind: snippet (source <path>)`; its benign twin exits 0. The seat and source are new on the line.

M ten forms in one file give ten lines, duplicates once. B depth: 6 nested wrappers resolve, a 7th is a finding (existing `_MAX_DEPTH`); a command over 500,000 bytes is a finding. I `scan_entry`, the CLI and `facilitator.run_backend` give the same findings for the same file. E undecodable base64, a wrong-encoding `-EncodedCommand`, a verb built from a variable: findings (fail closed); a decoded payload that is itself encoded is followed to depth 6. S the card 227 forms still pass their existing tests untouched.
