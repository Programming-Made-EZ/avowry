Round 1 (architect, developer, decider, agile coach: NO OBJECTION; QA and audit lens: OBJECTION, each with one condition; votes in .mob/records/decisions/rerank-26-r2.json). - Condition 1 (QA), adopted: red-first checks prove that invalid actors, missing consumer value, head-size excess and closure or edit failures are rejected before any change is applied.
- Condition 2 (audit lens), adopted: a git-tracked script and artifact map the snapshot deterministically to every closure, every value edit and every rank move, so compliance is auditable from git alone.

What the amendment adds (and all of it), as a precondition of the apply step:
- A1. The verdict artifact is committed before the apply: .mob/records/reranks/rerank-26-open-issues.json (the snapshot of the 202 open issues at the window's HEAD) and .mob/records/reranks/rerank-26-verdicts.json (every closure with its reason, every duplicate with its survivor, every consumer-value edit, every story-line correction, and the order). The note above is generated from them.
- A2. A committed script, scripts/board/apply_value_verdicts.py, validates the artifact against the snapshot and applies it. It is built test-first: its tests (tests/test_apply_value_verdicts.py) are written and committed failing before the script exists. The script refuses (non-zero, nothing applied) when: a consumer is not product owner, Morgan, Dana or Ari (or names a mob role: facilitator, driver, reviewer seat, agile coach, audit lens, Decider, script, CI, board); a kept contract or story has no value ("so that ..." text); a closure has no reason; a duplicate names a survivor that is itself closed as waste or not on the board; an issue is both closed and in the order; the order puts more than 4 bugs above the first product card (196); or an issue in the artifact is absent from the snapshot or already closed.
- A3. The script defaults to a dry run that prints every action (close N with reason, edit N with the added line, rank command). With --apply it runs the closures and edits first, reads each issue back, and stops without touching the rank order if any step fails; the rank edit (scripts/board/rerank.py --apply) runs last. It writes the apply log (every action and the read-back result) to .mob/records/reranks/rerank-26-apply-log.json.
- A4. Nothing is closed or edited by hand: the apply step is the script, the log is committed, and a reader can recompute the plan from the two artifact files in git.
