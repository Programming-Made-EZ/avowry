## 2. Assertion design of the single Pending test (criteria 1 and 2)
- Parser: standard library only (`python -c "import yaml"` fails locally with ModuleNotFoundError; no requirements file; no CI step runs pip). Glob `.github/workflows/*.yml` and `*.yaml`; job headers `^  (\S+):\s*$` under `jobs:`; a job ends at the next line indented 2 or less; `runs-on:` is `^\s+runs-on:\s*(.+)` with quotes and `#` stripped, a flow list `[a, b]` split; `dotnet-version:` is `^\s+dotnet-version:\s*(.+)`, a `|` block read line by line; a dotnet job contains `uses: actions/setup-dotnet`; matrix keys `os`, `dotnet-version` and `runs-on` under `strategy:` and `matrix:` as `- v` items, `[a, b]` lists or `- os: v` in `include:`; a leftover `${{` or a dotnet job with no pin is a failing check saying to extend the parser. Today this yields jobs `test` (ci.yml:52, :59) and `usable-v1` (:74, :81): `ubuntu-latest` and `8.0.x`; `mob-process` has no dotnet. A non-vacuous guard: at least one pin and one `runs-on`.
- Forward match: each dotnet-job `runs-on` value and each `dotnet-version` value appears on the page as a whole token, regex `(?<![\w.])VALUE(?![\w.])`.
- Reverse match (only values parsed from the workflows): SDK tokens on the page `\b\d+\.\d+\.(?:x|\d{3,})\b` must each be a workflow pin; OS tokens `\b(?:ubuntu|windows|macos)-[\w.]+\b` must each be a `runs-on` value from any job. So the page must not write `windows-latest` as an example, nor `0.1.0` or other three-part numbers.
- Prose checks (CRLF and whitespace normalised; a paragraph is a blank-line-separated block; each check independent with an id): `architecture` (one sentence contains `architecture` and `unpinned`; a second check records that the workflows name none and fails with an update-the-page message if one appears); `untested` (one paragraph contains `untested`, `try`, `.NET 8 SDK` and `other operating system`); `dotnet-first` (one paragraph contains `net8.0`, `.NET 8 SDK`, `ASP.NET Core runtime` and `not enough`; a separate check fails if the page contains `DOTNET_ROLL_FORWARD`); `local-feed` (the page has `dotnet tool install Avowry`, `--add-source`, `local feed`, `not published` and `public registry`); `commands` (for every bash, sh or shell fenced block, the text since the previous block or heading has a line starting `Run from:` and one starting `Needs:`; after the block a `powershell` or `pwsh` block or a line `Same in PowerShell.`; a block containing a `\` line continuation, `/tmp/`, `~/`, `$VAR` or `curl` must have a real powershell block; the page contains `dotnet --list-sdks`, `dotnet pack` and the install command; each block reported by index).
- Aggregation: the test collects `"<id>: <message>"` strings and ends with one `self.assertEqual([], failures, header + "\n".join(failures))` (the pattern of `Checks.AssertAll` in PackedToolIsVersionedInstallsAndBuildsTheDemo.cs), so a labels-only page passes the forward match and fails architecture, untested, dotnet-first, local-feed and commands.
- Missing page: `read_page()` returns None; the first failure is `page: docs/PREREQUISITES.md is missing` and every page check appends `blocked: page missing`; the result is an AssertionError, not a FileNotFoundError.
- Header text: if a workflow gains `runs-on`, a matrix or a pin (for example card 177 adding a Windows job), update docs/PREREQUISITES.md in the same change.
- Self-tests in the same module (they pass on the pre-change tree and run on embedded text): the parser reads a synthetic matrix workflow; a labels-only page fails every prose check; a minimal compliant page passes with an empty failure list (proving each check can be satisfied); the red record shows the one Pending test failing among N.
