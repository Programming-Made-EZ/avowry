## One thing I would do differently

Before writing a green, I would build one deliberately wrong checker from the red alone and run the red against it, then read every test that fails for a reason other than the rule it is named for. On 3186c15 five of six mutants survived the red class because each test also failed through an unrelated check; on b88e0b5 the red's default tree left 15 existing tests failing; on 042bf79 the red contradicted itself. Each time I learned it after the checker was written. Running one mutant per rule against the red first would have named the gap to the QA seat before the green, not in a commit body afterward.
