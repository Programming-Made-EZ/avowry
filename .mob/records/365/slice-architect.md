## 2. Design for card 365

All in facilitator.py except `start_voters` and `verify_history` in decider.py. No existing test reads `seat_use_seen`, so its meaning is free to change.

Lock helper:
- Constants: `SEAT_USE_LOCK = "mob-seat-use.lock"`, `SEAT_USE_LOCK_WAIT = 30.0`, `SEAT_USE_LOCK_POLL = 0.05` (plus random jitter up to the same), `SEAT_USE_LOCK_MAX_AGE = 120.0`, `SEAT_USE_LOCK_GRACE = 2.0`.
- `seat_use_lock_path(checkout) -> Path | None`: same shape as `decider_lock_path`, via `git rev-parse --git-path mob-seat-use.lock`; resolved once per CardRun and cached before taking the lock. Main checkout gives `.git/mob-seat-use.lock`; a linked worktree gives its own git directory (matches the per-worktree `.mob/records` file); outside git it fails with rc 128 and returns None.
- `hold_seat_use_lock(path, who, wait=None)`: context manager raising `SeatRefused`; `wait=None` reads `SEAT_USE_LOCK_WAIT` at call time so tests can patch it. `CardRun.seat_use_lock(role, context)` wraps it, sets `self._seat_use_held`, is not reentrant (a nested take raises RuntimeError).
- Take: `os.open(path, O_CREAT|O_EXCL|O_WRONLY)`, write JSON `{"pid","started" (real UTC time, never run.clock),"token","who"}`, close at once (the holder keeps no handle). `FileExistsError` or `PermissionError` (delete-pending on Windows) means busy.
- Stale rules on busy: the pid is not alive (`pid_alive`, already in facilitator.py); content unreadable or empty and mtime older than 2 s (killed between create and write); `started` older than 120 s whatever the pid says (pid reuse, failed release). A stale lock is swept: re-read, unlink only if token and content are unchanged. Residual risk: two sweepers race for microseconds; the prefix rule and the position check are the safety net.
- Wait and refusal: poll up to 30 s, then `SeatRefused("the <role> seat in <context> cannot start: the seat-use lock <path> (mob-seat-use.lock) is held by pid <pid> (started <ts>) and was not released within 30 seconds; no line was written. Delete it only if that process is gone.")`.
- Release: read the file, unlink only if the token is ours, retry about 2 s on OSError (antivirus, a reader's handle); if it cannot be removed, overwrite with `{"pid": 0, "released": true}` (swept by the pid rule). Release runs in `finally`. A killed process leaves a lock with a dead pid (or an empty file), swept by the next taker.
- No `msvcrt`/`fcntl`. On Linux `os.kill(pid, 0)` (zombies count alive until reaped, so tests `wait()` their dead-pid helper). Prototype on this Windows machine (`<scratch>/repro/lock_proto.py`): 6 processes x 40 sections gave 0 violations in 2.7 s, no lock left, a dead holder swept in 0.145 s, a live holder refused after 0.52 s with a 0.5 s wait, an old empty lock swept.
- Single-writer fallback: if `seat_use_lock_path` is None (not a git checkout), use a process-local `threading.Lock` keyed by the resolved history path and print one stderr warning per process: `seat-use lock: <repo> is not a git checkout; serialising within this process only` (about 30 existing tests use non-git temp repos). If the git directory exists but the lock cannot be created or waited for, refuse with the named error; the run never proceeds unlocked. The only stderr-empty assertion found is test_card_mode.py:1129 (a dry run that never reaches the gate).

What runs under the lock:
- `start_voters(run, seats)`: (1) compute the judged seats with the same filter and order as `check_voters` (extract a small helper); (2) before the lock, `run.reprobe_if_stale(f"stale before turn {run.turn_no + 1}", seat, role)` for the first judged voter; (3) `with run.seat_use_lock("decider voter", run.card.id):` run `check_voters`, `commit_voters`, then `written = run.read_seat_use(...)`; (4) after the lock build records with `voter_record(run.probes, voter.backend, index, written[:index])` where `index = run.seat_use_index[voter.context]`.
- Inside the lock, `reprobe_if_stale` raises `SeatRefused("the probe went stale while waiting for the seat-use lock...")` instead of probing; it never probes under the lock.
- `check_voters` and `commit_voters` keep their signatures and stay lock-agnostic (the existing CommitVoters tests call them directly).
- `gate_seat` (card mode): when `seat is None or self.probes is None` behave as today; otherwise refresh the probe, take the lock, run `commit_seat(role, check_seat(...))`.
- `verify_history(run)` takes the lock for its single read. Never under the lock: probes, `vote_seat`, snapshots, the vote lock. The seat-use lock and `hold_vote_lock` are never nested (the vote lock is taken after `start_voters` returns and released before `verify_history`).

Prefix rule:
- `read_seat_use` refuses with the existing message unless `lines[:len(seen)] == seen` (when seen is not None); then `seen = lines` (the whole file).
- `append_seat_use(...)` returns the written line's position (was None): read the bytes before writing to get `base = len(existing.splitlines())` and the `unterminated` flag; write; re-read through `read_seat_use` (prefix check against the old seen, then seen = whole file); require `lines[base] == text` else `SeatRefused("its line is missing after the write")`; store `self.seat_use_index[context] = base`.
- `commit_seat` still returns the probe and still sets `quota_reasons` from the judge-time `history`. Foreign lines already in `seen` are protected afterwards.
- `line_index` is the verified position of the voter's own line; `before = written[:index]` (the `voter_record(probes, seat, line_index, before)` signature is unchanged). Under the lock `index == len(lines at judge) + n`, so existing expectations hold (`[2, 3]` for a two-line seed).

## 6. Risks

- Windows locking and antivirus: `PermissionError` as busy, no handle held by the holder, retries on release, the pid-0 rewrite; do not use `msvcrt.locking` (readers get PermissionError).
- Pid reuse: bounded by the 120 s max-age rule; the wait is 30 s. Two sweepers: a microsecond race, backstopped by the prefix rule and the position check.
- Linked worktree: the lock is per worktree and matches the per-worktree history file (verified).
- Linux CI: the git binary is present; `os.kill(pid, 0)`; the barrier fakes use file polling; test 1a takes about 2 s; the dead-pid helper must `wait()`.
- The parallel launcher (scratchpad, not in the repo) needs no change; a killed run leaves a sweepable lock; it passes no `--ref`, so the card is "decider" and the contexts are `decider-<seat>`; the stagger can be removed after the live proof.
- Stale prompt files: today neither checkout's root holds any `prompt-*.txt`; after card 374 a crashed probe leaves its file in scratch; old files in a root would show in both snapshots and cause no diff.
- `probe_all.py` has the same root-cwd hazard (finding 9).
- Fallback warning: if a test elsewhere asserts empty stderr in a non-git decider path it would trip; the full suite run by the green will show it; none found by search.
