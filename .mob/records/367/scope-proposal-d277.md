# D277: card 367 reads a vendor page through the built-in browser when web fetch is refused

Proposer: the facilitator, 2026-11-16 about 17:42Z.

Evidence: the green seat (ctx-367g, claude sonnet) fetched Google's and GitHub's terms by web fetch, but every official xAI and OpenAI terms URL it tried answered 403 Forbidden to web fetch (x.ai/legal/terms-of-service, x.ai/legal/acceptable-use-policy, openai.com/policies/terms-of-use, usage-policies, service-terms and others; listed in .mob/records/367/green-record.md). It stopped instead of writing from memory, as its brief required. The card's "Not in this card" line excludes "reading terms by any means but web fetch".

Change to card 367's scope:
1. When web fetch of a vendor's official public terms page is refused, the page may be read through the built-in browser pane: logged out, no account, no terms accepted, non-essential cookies declined, the page's visible text only.
2. The facilitator does that read and saves each page's text with its URL and UTC time under .mob/records/367/captures/ (records only, as evidence). The green seat writes the summary from those captures and cites the official URLs; the page's "How this was read" section says which vendors were read this way.
3. Everything else in the card stands: no login, no legal advice, no change to pushed rows.
