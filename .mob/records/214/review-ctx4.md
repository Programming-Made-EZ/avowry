## Findings

1. LOW, Support/GeneratedApi.cs:145-196 (WaitUntilListeningAsync): the 500 ms ExitSettle is a heuristic, not a guarantee. Needed for guard 6 (a child that prints its address and leaves still accepts a connection briefly) and correct for that case: HasExited is checked before each probe and again after the settle, and the exit message drains both pumps. Cost: a fixed 0.5 s per successful start (about 15 real-API starts plus QuietChild starts in the suite, run in parallel, so well under 10 s of wall time). A real Kestrel prints the line only after it is bound and the hosted services started, so "prints then dies within 500 ms" is rare; a death after 500 ms is caught by the test's first request. Not in the slice: it is disclosed in the commit 5 body. Fix: none required; add one comment line saying 500 ms is a bound on the print-then-exit race, not a proof.
2. MEDIUM (process, not code), commit 5b afa4e40 Support/ThreadPoolFloor.cs:12-16: a global SetMinThreads(128,128) module initializer. It is a mitigation of the starvation, not a removal of its source: the sources are the sync ReadToEnd/WaitForExit calls on pool threads in other test classes. It is test-assembly only (net8 has no AppDomain split; process-wide for the testhost only) and changes no assertion. The diagnosis in the commit body (line already in the log, waiter continuation late) is plausible and consistent with my numbers (see F-062). Side effect: other tests see a different thread-injection schedule; none failed because of it in my runs. Fix: call it a mitigation in the comment, and file the sync-over-async tests as a bug card; do not claim "cause-level".
3. LOW, Guard_hook_is_null_by_default_and_fires_once (GeneratedApiSeams.cs:20-45): the admitted blind spot (hook called twice) is real for this test, because its hook throws on the first call. It is covered elsewhere: Guard_bind_failure_starts_exactly_one_process counts starts through a non-throwing hook and asserts 1 (GeneratedApiBoundAddressEdges.cs:152-163). So a double Invoke turns that guard red. Accepted; fix optional: name that cross-cover in the guard 1 comment.
4. LOW, kill discipline: DisposeAsync (GeneratedApi.cs:104-129) kills only `_process` when `_process.Id == Pid` (recorded at construction); the child is `dotnet <dll>` with no wrapper, one PID. Unchanged by the card. RunToEndAsync likewise kills its own PID. Verified by reading both and by the source scan checked set. No finding.
5. INFO, ubuntu CI: no flakiness source found in the card's code. Path is case-correct (QuietChild.dll), net8.0, `Now listening on:` is parsed per line and unanchored, the env override `Logging__LogLevel__Microsoft.Hosting.Lifetime` is valid on Linux, HTTP(S)_PORTS and DOTNET_URLS are cleared.
