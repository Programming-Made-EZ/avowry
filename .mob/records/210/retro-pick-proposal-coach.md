# Retro pick proposal (agile coach seat): the pre-ship gate states its shell and checks a failure in the reference shell

Card 210 retro, 2026-11-02. Proposer: agile coach seat. For a Decider. Sources: docs/retros/card-210-2026-11-02.md section 5; voices in .mob/records/210/retro-voices.json; facts in .mob/records/210/retro-input.md; the sign-off .mob/records/210/signoff-ctx6.md section 6; the gate .mob/records/210/preship-gate.md; the in-progress record .mob/records/210/record-in-progress.json; the queued inputs .mob/records/notes/2026-11-01-queued-retro-and-template-inputs.md and the open proposal-labelled issues.

Decider (number set at recording), the card 210 retro process pick, as an experiment

PICK: every pre-ship gate report opens each test run with an Environment line (the shell and how it was launched, the working directory, the commit hash), and every failing test in a module that no commit of the card touches is re-run, failing modules only, in the reference shell, with its own Environment line, in the same report and before the verdict. The reference shell is the one in which the card's greens and the facilitator recorded their full-suite results; the facilitator's gate brief names it. (Proposed by the architect voice, shell and repo provenance for every gate run, and the audit-lens voice, a normalised recipe in the report; the decider voice and the sign-off seat ask for the same plain-shell run.) The line-ending check, the Copilot decision-seat fix and a circuit breaker, parallel windows, test-impact analysis and the refactor proposal are deferred or routed to cards, not rejected.

User benefit: the product owner gets one gate verdict per card that does not have to be reversed. Card 210's HOLD was overturned 43 minutes later by the same code, about 15 percent of the card's 4 hours 45 minutes, and cost a second 25 minute full-suite run by the facilitator and 8 minutes 26 seconds of a re-check seat.

Why this one: it is the largest avoidable cost on this card that the team can change, and it is the cheapest.
- The gate started at 15:40 UTC and the HOLD (d20314c) landed at 16:14: two failures in tests/test_mob_summary.py, from a 1545-test run of 1520 seconds. The re-check (3d03129) returned SHIP at 16:57 because the same tests pass in a plain bash shell (1545 OK, 528b3d9) and no card 210 commit touches them. From the HOLD to the SHIP was 43 minutes; the gate and its re-check took 36 minutes 50 seconds of Copilot seat time.
- The first report named no shell. The record learned it afterwards: PowerShell into cmd /c. The sign-off says a rule that the gate states the shell it runs the suite in would have saved one of the two runs. The gate's evidence for "plain shell passes" is the facilitator's run, not its own, which the sign-off lists as a weakness.
- The HOLD was not wrong. The failure is a real portability bug (card 268: the tests pass in one shell and fail in another), and only a seat in a different environment could find it. The pick does not try to stop that finding; it asks the report to carry both results so the verdict does not need a second round.
- Five of seven voices named the gate's environment in some form: the architect (shell and environment provenance), the audit lens (a git-only reproducibility packet with a normalised shell recipe), the decider (run the gate in a plain shell too), the coach (no Copilot CLI suite runs until card 268) and the QA engineer (replace the gate seat). Their wordings differ; the common lever is "say where it ran, and check a failure where the others ran".
- It extends the gate's existing report and the brief the facilitator already writes. It adds no gate, seat, file or meeting (issue 245's test).

Why not the others: the line-ending check (QA engineer, decider, developer and audit-lens voices) answers one event that sign-off caught, and bug card 269 (restore LF or add .gitattributes) may remove the need for any check; if it recurs it is the next candidate. The circuit breaker (product manager and coach voices; issue 242 point 2) and parallel windows (card 265) are decider.py changes, and the Copilot decision-seat fix (card 229) is ranked third by re-rank 18 and removes the cause. Test-impact analysis (developer voice) is a tooling build. The refactor-step proposal (issue 260) is a standing-rule change for its own Decider. Details in the retro, section 5.

HYPOTHESIS: We believe that a gate report that states where each test ran and shows a failing module's result in the reference shell reaches its final verdict in one report, instead of a HOLD and a re-check, when a failure comes from the gate seat's environment, without letting a real failure through. We will know when, over the trial, no HOLD is overturned for environment, no defect the gate passed is found later in its scope, and the counter-metrics do not rise.

RULE UNDER TRIAL:
C1. The facilitator's gate brief names the reference shell from the card record: the shell in which the greens' and the facilitator's full-suite results were recorded (card 210: plain bash, 1475, 1517 and 1545 OK), and how to start it. The gate seat runs the full suite there when it can.
C2. Before each test result the gate report carries one Environment line: the shell and how it was launched (for example "Copilot CLI direct", "PowerShell into cmd /c", "bash -lc"), the working directory, the output of git rev-parse HEAD, the command, the test count and the seconds. A run without that line is not counted as evidence.
C3. On a failing test the gate lists the failing test ids and shows by git whether any commit of the card touches the failing module or what it calls (as the card 210 re-check did with git log and git show --stat). If none does, it re-runs the failing modules only, not the full suite, in the reference shell, and writes the result with an Environment line in the same report before the verdict.
C4. A gate seat that cannot start the reference shell says "environment-unverified" and the verdict is HOLD. The facilitator then runs the same failing modules in the reference shell and records that as the facilitator's run in the same report file, not as the gate's.
C5. Verdict rules otherwise unchanged. A failure that fails in both shells, or in a module the card touches, is a HOLD. A failure that fails only in the gate's shell, passes in the reference shell in the gate's own report and is touched by no card commit is written "environment-dependent"; the facilitator files a bug card at once (card 268's form) and the gate may SHIP with that bug listed. A gate that did not itself see the reference-shell pass may not SHIP on it.
C6. Not changed: the independent reviewer owns the verdict; the full suite still runs once at the gate; sign-off and the auditor; D175's cap rule, D168, D171, D174 and the green commit-then-suite rule; card 268's own fix. No new meeting, seat, file or gate. During the trial the facilitator adds C1 to C5 to the gate brief and the sign-off checklist. Only a keep verdict goes to the mob-defaults template, through the normal template-change path including the template review.

METRIC: HOLDs overturned for environment, per gate: a HOLD followed by a SHIP on the same code because the failing tests pass in the reference shell and no card commit touches them. Read from the gate files and the commit times. Card 210: 1 (HOLD d20314c 16:14 UTC, SHIP 3d03129 16:57 UTC, 43 minutes, one extra 25 minute suite run, 8 minutes 26 seconds of re-check seat). Target: 0 over the next 3 gates. Context figure, not a target: minutes from the first gate verdict to the final one (card 210: 43). A gate with no failing test gives no reading on this metric and is counted for C2 only.

COUNTER-METRICS: (1) defects the gate report passed that sign-off, the auditor or a later card finds inside the gate's scope (card 210: the line-ending rewrite in green 3, found by sign-off, which this pick does not cover; tests: 0); a gate that SHIPs past a real red would show here. (2) HOLDs that are real, failing in both shells or in a module the card touches (card 210: 0); a gate that never HOLDs across three cards is a reading to set against (1). (3) Gate seat minutes per gate (card 210: 28 minutes 24 seconds first run, 8 minutes 26 seconds re-check; the failing module alone took 193.6 seconds direct and 188.5 seconds through cmd /c), the cost of C3. (4) Open environment-dependent bug cards at the end of the trial and days open (card 268 was filed at the gate and open at sign-off); if failures are shipped past and left open, the cost has moved to the backlog. Evidence for the trial retro, not targets.

TRIAL SCOPE: the next 3 pre-ship gates whose brief is written after this Decider is recorded, of any seat or model; a gate with a re-check counts once. If card 268 lands first and no failure appears, the trial reads C2 only, and the trial retro may propose a longer run by its own Decider. The trial retro decides keep, revise or drop by Decider.

ACCOUNTABILITY CHECK: at the sign-off read, the sign-off seat checks that each test result in the gate report has an Environment line, that the reference shell is the one the brief named, and that each failing module has its reference-shell result or the words "environment-unverified". The facilitator checks the hash in each line against the card's HEAD in git. A report missing any of these counts as not run; the auditor tick may FAIL it. The checker is the sign-off seat, re-checked by the auditor.

NO BLUR: D175 (cycle caps), D168, D171 and D174 keep their own metrics; a HOLD caused by a cap breach is not scored here. This pick is scored on HOLDs overturned for environment, not on card duration. A fix to card 268 that removes the failure is credited to card 268, not to this pick. The line-ending rewrite stays with bug card 269.

BASELINE (card 210): one gate HOLD (two failures in tests/test_mob_summary.py; 1545 tests in 1520 seconds in the gate's PowerShell-into-cmd shell), a re-check SHIP, the facilitator's plain-bash full run 1545 OK; a first report with no shell statement; 43 minutes from HOLD to SHIP; 36 minutes 50 seconds of gate-seat time; no Environment lines.

COST (issue 245): one brief line (C1), one Environment line per test run, and one extra module run when a test fails (about 3 minutes in card 210's case, none when the suite is green). No extra seat or meeting. If the cost shows in the trial it is the first thing the retro cuts.

REVERSIBILITY: two-way door. Remove the lines from the gate brief and the sign-off checklist; no shared state, checker or earlier D-record changes. C5 reverts to "HOLD on any red suite".

A reasonable, reversible condition is adopted and the proposal re-polled; a later round may not add new demands. Only an irreconcilable purpose or model conflict escalates. Independent fresh-seat re-run before recording. Each reply ends with one line "CITE: <point>" as D171 C1 says.
