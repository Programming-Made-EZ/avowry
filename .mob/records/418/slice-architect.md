## 2. Design

- ONE pure, platform-independent function `public static class PathScrub { public static string Apply(string? text) }` (global namespace), regular expressions only, never Path.GetFileName (on Linux `\` is not a separator). Roots, each at a word boundary: drive `X:\` or `X:/` (with an optional `Users` segment recorded as the home marker); UNC `\\host\`; tilde `~\` and `~/`; rooted `/home/`, `/Users/` (both home markers), `/root/`, `/tmp/`, `/var/folders/`, `/private/var/folders/`, and `file:///home/...` through a lookbehind for `file://`. Not in the ruling and left to the facilitator: Git Bash `/c/Users/` and `/mnt/c/Users/` (left unscrubbed). Segments: a non-final segment `(?:<[A-Za-z]+>|[^\\/\r\n"'`|*?:;,<>\[\]])+` (spaces, parentheses and `~` allowed, so a spaced account and `Program Files (x86)` work); a final segment `(?:<[A-Za-z]+>|[^\s\\/"'`|*?:;,()<>\[\]])*` (stops at whitespace, quotes, `(`, `:`, `,`, `;`, `]`, so `Candidate.cs(7,1)` leaves `Candidate.cs` and `(7,1)`; two paths on one line are not merged). Replacement per match: empty `file` (no file segment) gives `<path>`; a home marker with no `dir` captures (the last segment is the account folder itself: `C:\Users\<user>`, `/home/<user>`) gives `<path>` (the account name is never written); otherwise the file's short name. The `<[A-Za-z]+>` alternative lets `<user>` and `<scratch>` placeholders sit inside a path. Must NOT touch: `</Project>`, `https://host/path` and `https://example.com/home/x` (a letter precedes `/home/`), relative names (`obj\Debug\x.cs`, `src/a/b.cs`), a bare `/a/b`, `Build FAILED.`, `tests_did_not_run`, the CS0117 and CS0029 message lines. Idempotent (`<path>` is not rooted). Known limits to document: prose between two rooted paths on one line with no `: , ; quote ]` between them collapses to the last path (over-scrubbing, safe); `%USERPROFILE%` and `$HOME` text is not scrubbed (no account name); a custom Linux TMPDIR outside the five roots leaks a folder, not the account name; `\\?\C:\...` leaves `\\?\` plus the short name. Linear (disjoint character classes), no timeout.
- One implementation per tool by a LINKED source file: `tools/Avowry.Bench/PathScrub.cs` (SDK globbing includes it) and in Avowry.BenchCs.csproj `<Compile Include="..\Avowry.Bench\PathScrub.cs" Link="PathScrub.cs" />`; smaller and safer than duplicating (one copy of about 25 lines, no drift guard; the test project already references Avowry.Bench so a table test calls it directly; BenchLauncher's staleness check already watches tools/Avowry.Bench/*.cs; not a new kind of tracked file: a `tools/Shared/` folder would be one under D249). Alternative: duplicate (card 368 style) plus a drift guard like cold_profile_literals_cannot_drift_between_benchmark_arms (CSharpBaselineAcceptance.cs:11 to 23).
- Where applied: scrub the raw text, THEN cap. C# tool: line 242 `var output = PathScrub.Apply((await stdout) + (await stderr));` (covers CompactFailureSummary and tests_did_not_run before the cap); line 264 in ReadTestResult (scrub each message before FirstLine); the score text is then scrubbed so diagnostics[^1] at 178 carries the same text into the retry prompt; `error`: in CreateResult (837 to 840) for Diagnostics and Error (or at 189 and 190); in Persist (842) before serialising, on every Diagnostics entry, Error and Label. Scrub Diagnostics entries, Error and Label; leave Model, Task, PromptHash, Mode and constants; ColdFlags holds `<scratch>` (not rooted) and is unchanged.
