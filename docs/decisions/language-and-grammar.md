# Language And Grammar decisions

Language syntax, semantics, vocabulary, and domain-neutral authoring rules.
Compiler mechanics and delivery history belong in their own area files.

## In force

- [D20](#d20) — Consumer-observable outcomes: a missing failure-path spec is an error, an endpoint with an output cannot say succeeds
- [D21](#d21) — Async and events stay out of the core grammar: they are declared effects plus base-library keywords, specified with a virtual clock and event capture, kept as a…
- [D29](#d29) — The spec concept is not a keyword yet: measure under today's grammar first, then an ADR and a spike
- [D30](#d30) — The spec concept is named actor, in the use-case sense: anyone or anything outside the system that interacts with it, human persona or system actor
- [D72](#d72) — The scored Phrase arm's documentation is the frozen cheat sheet with recorded hashes
- [D89](#d89) — Language layering: a domain-neutral core plus one extension per application domain, web first; the adapter axis is orthogonal to the domain axis
- [D105](#d105) — Logic sources are layered: core library and syntax first, language adapters' idiomatic implementations second, LLM generation from specs third, native block last

Related decisions: [D3](board-and-delivery.md#d3), [D70](benchmarks-and-measurement.md#d70), [D86](board-and-delivery.md#d86), [D93](compiler-and-adapters.md#d93), [D95](compiler-and-adapters.md#d95), [D99](benchmarks-and-measurement.md#d99), [D101](process-and-staffing.md#d101)

- Direction recorded (product principle, layered): implementation logic comes from sources in this order. (1) Core: the library and the syntax; universal patterns such as validation and guard steps and record update are written in Phrase syntax and the base library so logic leaves native blocks and becomes portable intent (cards 159 and 160). (2) Language adapters supply idiomatic, high-quality implementations of the library patterns for their language, chosen by the library binding and project profile, so generated code is idiomatic and not a raw translation. (3) LLM generation fills the gaps from the phrase's specs, guided by adapter idioms and verified by the generated tests. (4) A native block stays as the escape hatch. Consequences: .phrase holds intent and specs, not target-language code; the share of logic still in native blocks is tracked as a trade-off signal, not a target; improving the generated C# belongs in the C# adapter, not the core. Cards 159 and 160 state how their patterns map through the C# adapter.
- Evidence: docs/adr/ADR-library-binding-layering.md (layers, logic sources in order with worked examples for the ensure step and the record update, FastEndpoints audit with paths and line numbers checked by scripts/check-library-binding-layering.py, hard-wire rule, second binding only on a real need, a profile sketch marked not implemented); gate 243 compiler and 169 acceptance tests pass; Python tests pass.
